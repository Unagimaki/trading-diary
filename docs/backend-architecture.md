# Архитектура backend

## Структура

```text
backend/
├── cmd/api/                     точка входа процесса
├── internal/app/                сборка зависимостей и жизненный цикл сервера
├── internal/config/             чтение конфигурации окружения
├── internal/domain/             сущности, правила, сервисы и интерфейсы репозиториев
├── internal/infrastructure/     PostgreSQL и файловое хранилище
├── internal/transport/http/     mux, handlers, middleware и HTTP DTO
└── migrations/                  версионируемая схема PostgreSQL
```

## Domain

Каждый пакет отвечает за отдельную предметную область:

| Пакет | Ответственность |
|---|---|
| `auth` | Пользователи, пароль, сессии |
| `journal` | Журналы и настройки расчётов |
| `column` | Динамические колонки, типы и системные роли |
| `observation` | Строки, ячейки, валидация и автопересчёт |
| `attachment` | Ограничения и жизненный цикл изображений |
| `analytics` | Формирование аналитического отчёта |
| `quality` | Поиск противоречий в торговых данных |

Domain-сервис оркестрирует use case и работает через интерфейс `Repository`. Он не импортирует PostgreSQL или HTTP transport.

## Transport

`internal/transport/http` содержит:

- регистрацию маршрутов gorilla/mux;
- декодирование и проверку формы HTTP-запроса;
- извлечение пользователя из сессии;
- сопоставление domain-ошибок с HTTP-статусами;
- единый JSON-формат ошибок;
- middleware логирования, request ID, panic recovery, CORS и метрик.

Handler должен следовать цепочке: `decode → authenticate → service → map error → encode`.

## Infrastructure

`infrastructure/postgres` реализует domain-репозитории. Запрос обязан одновременно ограничивать ресурс по его ID и `user_id`; одного UUID ресурса недостаточно.

`infrastructure/storage` хранит бинарные файлы. В PostgreSQL остаются метаданные и связь изображения с пользователем, журналом, строкой и колонкой.

## Composition root

`internal/app/app.go`:

1. создаёт pool PostgreSQL и проверяет соединение;
2. создаёт реализации репозиториев;
3. передаёт их domain-сервисам;
4. создаёт router и HTTP server;
5. обрабатывает штатное завершение процесса с timeout.

## Транзакции

Транзакция требуется, когда use case меняет несколько связанных записей, позиции строк/колонок или метаданные вместе с файлом. Граница транзакции должна соответствовать одному бизнес-действию, а не отдельному SQL-запросу.
